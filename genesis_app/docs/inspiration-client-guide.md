# Inspiration 灵感回复：客户端对接

更新日期：2026-09-09。状态：已实现并通过验证，尚未发布。统一通过生成接口复用或生成回复，成功生成后自动保存。客户端不再传 `refresh` 参数。

## 生成灵感

```http
POST /aitown-chat/api/v1/worlds/{world_id}/locations/{location_id}/inspiration
Authorization: Bearer <token>
x-system-language: zh-CN
Content-Type: application/json

{"conversation_round_id":101}
```

登录态也支持现有 AIUSS Cookie。无需 WebSocket 连接或新增客户端版本门槛。world_id 为当前世界，location_id 为该世界内的聊天地点；登录用户须在世界内有绑定角色。

请求与响应统一使用 conversation_round_id，关联来源成功轮次，必须为正整数 int64。客户端从来源消息取同名字段，无损传输，不经过 JavaScript Number 丢失精度。来源须属于目标世界及地点。

客户端请求体仅包含 `conversation_round_id` 和可选 `card_id`，不传 `refresh`。按服务端默认行为，先查当前用户、世界、地点、来源轮次和卡片来源的最新成功记录，有则直接返回；没有才调用模型，保存后返回。

客户端不传 UID、历史正文、候选数量、模型、prompt_id 或 stream。服务端使用 p_inspiration/latest、stream=false，由模板选择模型及候选数量。

成功响应沿用 HTTP 200 envelope：

```json
{"err_no":0,"err_msg":"succ","data":{"conversation_round_id":101,"card_id":0,"source_card_id":0,"messages":["我想再听听你刚才提到的那件事。","要不要一起去附近走走？"],"gateway_request_id":"request_example"}}
```

messages 为非空字符串数组，按返回顺序展示，不要固定为三条。gateway_request_id 用于问题排查，可能为空，不作为消息 ID。保存成功后才返回成功；模型成功但数据库写入失败返回 5002。

## 按卡片关联

请求新增可选 `card_id`，为正整数 int64；省略或 null 表示该轮当前正式回复。0、负数、字符串均非法。显式指定时必须使用 cards 接口返回的真实 card_id，且只能读取本人卡组内已成功的卡片。

```json
{"conversation_round_id":101,"card_id":901}
```

| 场景 | source_card_id | 正文来源（需要生成时） |
|---|---|---|
| 原始回复尚未成卡 | 0 | 原轮正式 AI 回复 |
| 原始卡片已存在 | 0 | 原始卡片有效正文，包含卡片编辑；已采用该卡时使用正式正文 |
| 候选卡片 | 该卡真实 card_id | 该卡有效正文，包含编辑并过滤删除；已采用该卡时使用正式正文 |

省略 card_id 时，未采用候选前解析到原始来源，采用后解析到 selected_card_id；普通正式回复延续世界内有角色即可使用的权限，显式卡片/未采用内容需要卡组所有者权限。内部始终固定已解析的来源，不会在模型返回时重新按当前选择分配结果。

响应新增 card_id（请求解析时真实卡片 ID，尚未成卡为 0）及 source_card_id（稳定关联键）。原始卡片创建前后的 source_card_id 都是 0，原有灵感直接复用，不需要客户端搬迁记录。响应的 card_id 是请求开始时的状态，若期间成卡，以 source_card_id 匹配。

客户端按用户、世界、地点、conversation_round_id、source_card_id 缓存；由 cards 的 is_original 判断原始来源为 0，其余为 card_id。切卡时传对应 card_id；候选被采用后不传 card_id 也能复用它的灵感。轮次及卡片 ID 必须无损传输。

不使用 source_content_hash。编辑/删除原文不会使已有灵感失效，仍复用旧内容。无记录时，使用对应回复的最新有效正文生成。不同卡片的记录独立，互不覆盖。

## 复用与生成

首次打开或恢复候选均使用同一个 POST 接口，请求只传来源轮次和可选卡片 ID。

没有独立查询或保存接口。复用与生成返回相同结构，成功时 messages 均非空。复用时保留原 gateway_request_id 与候选内容，包括生成时使用的语言。

生成成功会追加保存整组结果，“最新”按保存记录 ID 倒序确定。不存在记录时不会返回空数组，而是尝试生成。并发请求没有去重保证：多个未命中请求可能各自生成并保存。

复用前仍校验登录态、世界角色、地点及卡片归属/状态；命中时不再读取历史正文或调用模型，即使来源已移出记忆窗口也可恢复之前的候选。查询失败返回错误，不按无记录处理。

## 客户端交互

1. 首次打开或恢复均不传 `refresh`。请求期间显示加载状态，避免重复点击。
2. 完整 JSON 返回后展示候选；不等待 WS ACK、chunk 或结束事件。
3. 选中候选后填入输入框，允许编辑；用户发送时沿用普通聊天流程。
4. 切换世界、地点、轮次或卡片时丢弃旧请求结果；使用本地请求序号避免旧结果覆盖新结果。

灵感不创建正式聊天消息或聊天轮次，不触发 P4。聊天或 Tick 正在生成时也可请求；需要生成时，使用截至 conversation_round_id（包含该轮）的已完成历史及当前世界设定，不推进聊天历史水位。生成时若来源早于用户已保留的记忆窗口，上下文预处理失败，返回 2007，需选择较新的来源。首版不扣 Gem、不限次数、不要求 Pro；最终发送消息仍遵循现有聊天规则。

## 失败与重试

业务失败仍为 HTTP 200，err_no 非零，data 为 {}。客户端按 err_no 判断业务结果，同时处理网络错误、非 200 响应及 JSON 解析错误。

| err_no | 含义 | 客户端处理 |
|---|---|---|
| 10001 | 登录态缺失或失效 | 进入现有登录处理 |
| 1001 | 参数无效或来源非有效轮次 | 检查参数，选择有效来源 |
| 10002 | 用户没有世界角色 | 提示先加入并绑定角色 |
| 1014 | 地点不存在 | 刷新地点信息 |
| 2012 | 无权访问指定卡片 | 使用本人卡片或省略 card_id 获取正式回复 |
| 2018 / 2019 | 卡片不存在 / 尚未生成成功 | 刷新卡片列表，等待生成成功 |
| 2007 | 上下文不可用、模型失败、超时或输出无效 | 结束加载，选用较新来源或手动重试 |
| 5002 | 数据库保存或查询失败 | 稍后恢复或重试 |
| 5003 | 世界等依赖服务失败 | 提示稍后重试 |

模型调用超时为 90 秒；客户端建议至少等待 100 秒，不自动重试生成请求。结果不明时可重新请求同一来源：有已保存结果就复用，没有则生成，因此该请求不是只读查询，也不保证模型只调用一次。失败时客户端可保留当前候选。错误文案为英文，不依赖文案做业务分支。
